# NewsCore AI — Step 0

> Документ v2 после фидбека Димы Гальченко (18.05.2026).
> Прошлая версия переусложняла: смешивала UI, продуктовое видение и логику матчинга. Эта переписана под **один первый шаг**.

---

## Что строим (одна фраза)

Скрипт/сервис, который по запросу пользователя на естественном языке идёт в заранее определённый список ресурсов, парсит свежие материалы и возвращает те, которые соответствуют запросу.

**Это ядро.** Всё остальное — фоновый мониторинг, доставка, UI, тарифы — строится поверх этого ядра. См. `roadmap.md`.

---

## Чёрный ящик

**Input:**
- NL-запрос пользователя (строка). Пример: «новости про курс валют», «сделки M&A в финтехе», «регуляторика для МСБ».
- Список источников (фиксированный, в конфиге).
- Опционально: окно свежести (по умолчанию — последние 7 дней).

**Output:**
- Список релевантных материалов: `{title, url, source, published_at, snippet}`.
- Формат вывода: JSON в stdout (или эндпоинт `POST /briefing`).

**Не output:**
- Суммаризация. На Step 0 берём оригинальные заголовки + сниппеты. Суммаризация — отдельный слой поверх (см. roadmap).
- Категоризация, сущности, importance scoring — всё не сюда.

---

## Архитектура (минимум)

```
NL-запрос
   │
   ▼
[Парсер источников] ── по каждому источнику собирает свежие материалы (RSS / HTML)
   │
   ▼
[Извлечение текста] ── trafilatura для тела статьи
   │
   ▼
[Матчер] ── оценивает релевантность материала запросу
   │
   ▼
Топ-N материалов в output
```

Никакого frontend'а. Никакой БД (для Step 0 хватает in-memory + локального кэша файлами). Никакого планировщика. Никакого деплоя.

---

## Ключевое решение: что такое «матчер»

Это **главный неизвестный** Step 0. Варианты для теста:

1. **Lexical** (BM25 / TF-IDF от запроса к телу статьи) — самый простой, быстрый, локальный.
2. **Semantic** (эмбеддинги — например `intfloat/multilingual-e5-base`, cosine similarity) — лучше для перефразированных запросов.
3. **LLM-as-judge** (на каждый материал — запрос «релевантно ли это запросу X?») — самое дорогое, но самое гибкое для NL-запросов.

**Подход:** в Step 0 пробуем 1 и 3 на 5–7 эталонных запросах (см. ниже), сравниваем результат глазами, выбираем что-то одно и фиксируем как baseline. Step 0 — это в том числе ответ на вопрос «какой матчер достаточно хорош для briefing-first».

## Definition of Done (Step 0)

- [ ] Запускается одной командой (`python -m newscore.briefing "запрос"` или `curl POST /briefing`).
- [ ] Источники описаны в конфиге, легко добавлять.
- [ ] Парсер работает по 3–5 источникам (см. вопросы команде).
- [ ] Матчер реализован минимум одним способом (см. выше).
- [ ] **Качественный тест пройден:** на 5–7 эталонных запросах (см. ниже) топ-N материалов выглядит релевантным — глазами проверяет команда + Дима.
- [ ] Логи показывают, что произошло на каждом шаге (какие материалы взяли, какие отбросили, почему).
- [ ] README с примерами запуска и одним скриншотом/выводом — чтобы Дима мог запустить у себя.

**Не входит в DoD:**
- Веб-интерфейс.
- Закреплённые темы / фоновый мониторинг.
- Доставка (email / Telegram).
- Суммаризация.
- Дедупликация одного события из разных источников (если не дешёво — выносим в roadmap).

## Эталонные запросы для проверки качества

Фиксируем до старта кодинга. На них меряем «работает / не работает».

1. «курс валют»
2. «ставка ЦБ»
3. «санкции против РФ»
4. «IT-импортозамещение»
5. «сделки M&A в финтехе»
6. (тёмная лошадка) «новости про автоваз» — узкая тема, проверка что не вернётся всё подряд
7. (стресс) «дай мне всё что было за неделю про сделки M&A в финтехе с участием Сбера и ВТБ» — длинный сложный запрос

Для каждого: ручной просмотр топ-10 источников за последние 7 дней. Команда формирует «ожидаемое» множество материалов. Потом сравниваем с тем, что вернул агент.

## Открытые вопросы (только блокирующие для Step 0)

1. **Источники для Step 0.** Дима сказал «потенциальных источников — ∞». Подтверждаем: для Step 0 берём конечный список из 3–5 (РБК / Коммерсантъ / Ведомости / Forbes Russia / Интерфакс)? Или другой?
2. **RSS vs полный краулинг.** В пайплайне идёт RSS → trafilatura по URL статьи. Это окей или Дима хотел сразу научиться брать произвольные URL без RSS-фида?
3. **Матчер.** Делаем все три варианта (BM25 / embedding / LLM-judge) и сравниваем, или фиксируем один сразу? Если один — какой? (Моя рекомендация — embedding как баланс качества/стоимости, но решающее слово за командой.)
4. **LLM-провайдер, если LLM-judge или embedding.** YandexGPT / GigaChat / OpenAI через прокси / локальный e5? У кого есть ключи?
5. **Кто пишет код Step 0 и к какой дате.** Если меня — иду по плану. Если команда — кто и сколько у нас времени до защиты?
6. **Качественный тест.** Команда (Maria? Влад?) готовит «ожидаемые» материалы по 5–7 эталонным запросам — кто и когда?
7. **Дедупликация.** Если в источниках одно событие в 3 материалах — в Step 0 показываем все три? Или базовая дедупликация (по URL + по похожести заголовка)?

Всё остальное (ежедневный дайджест, закреплённые темы, доставка, UI, тарифы, категории, NER, классификация) — **намеренно вынесено в `roadmap.md`** и обсуждается ПОСЛЕ того как Step 0 заработает.
