# NewsCore AI — Step 0

> Документ v3 (2026-05-20). Закрыты Open Q1–Q4 и Q7 (см. секцию ниже).
> Полная спецификация: `step0-spec.md`. Дорожная карта: `roadmap.md`.

---

## Что строим (одна фраза)

CLI-скрипт, который по NL-запросу пользователя идёт в 5 заранее определённых источников, парсит свежие материалы и возвращает релевантные через embedding-матчер.

**Это ядро.** Всё остальное — фоновый мониторинг, доставка, UI, суммаризация, тарифы — строится поверх. См. `roadmap.md`.

---

## Чёрный ящик

**Input:**
- NL-запрос пользователя (строка). Примеры: «новости про курс валют», «сделки M&A в финтехе», «регуляторика для МСБ».
- Список источников — в конфиге.
- Опционально: окно свежести (по умолчанию 7 дней).

**Output:**
- JSON в stdout: список `{title, url, source, published_at, snippet, score}` + метаполя (`partial`, `failed_sources`, `run_id`).

**Не output:**
- Суммаризация, категоризация, NER, importance scoring — всё в roadmap.

---

## Архитектура (минимум)

```
NL-запрос
   │
   ▼
[Парсер источников] ── RSS-фиды, источник-специфичные экстракторы тела
   │                     ├─ РБК: <rbc_news:full-text> прямо из RSS
   │                     └─ Остальные: trafilatura по URL статьи
   ▼
[Дедупликация] ── по URL
   │
   ▼
[Матчер] ── embedding-based (intfloat/multilingual-e5-base, cosine similarity)
   │
   ▼
Топ-N материалов в output
```

Без frontend'а, без БД (in-memory + файловый кэш), без планировщика, без деплоя, без HTTP-эндпоинта.

## Зафиксированные источники (5 шт)

Закрыто, см. `sources-research.md`:

1. **РБК main** — `rssexport.rbc.ru/rbcnews/news/30/full.rss` (полный текст прямо в RSS)
2. **Коммерсантъ** — `kommersant.ru/RSS/news.xml`
3. **Ведомости business** — `vedomosti.ru/rss/rubric/business`
4. **Интерфакс** — `interfax.ru/rss.asp`
5. **Forbes Russia** — `forbes.ru/newrss.xml`

Все проверены на доступность из РФ без VPN, свежесть < 3 ч.

## Зафиксированный матчер

**Must:** embedding-based — `intfloat/multilingual-e5-base`, cosine similarity между эмбеддингом запроса и тела (или title+snippet, если тела нет).

Обоснование выбора:
- Детерминирован → стабильные результаты.
- Локальный → нет зависимости от LLM-провайдера, ключей, rate limits.
- Хорош для коротких русскоязычных NL-запросов.
- ~280M параметров, на CPU работает в десятки секунд для нашего корпуса.

**Should:** BM25 (`rank_bm25`) — дешёвый baseline для side-by-side сравнения. Флаг `--matcher=bm25`. Результат сравнения — материал для решения, какой матчер брать в Step 1.

**Could:** LLM-judge — только если embedding + BM25 не вытягивают precision@10 ≥ 0.5 на эталонных запросах.

## Definition of Done (Step 0)

- [ ] Запускается одной командой: `python -m newscore.briefing "курс валют"`.
- [ ] Парсер по 5 зафиксированным источникам. Падение одного источника не валит остальные.
- [ ] Embedding-матчер работает, output — JSON в stdout.
- [ ] Дедупликация по URL.
- [ ] Структурированные логи каждого шага (JSON-lines).
- [ ] **Качественный тест:** на ≥4 из 7 эталонных запросов precision@10 ≥ 0.5 (≥5 из топ-10 — релевантные глазами).
- [ ] README — git clone → запуск за ≤5 шагов.

**Не входит в DoD:** веб-интерфейс, HTTP-эндпоинт, закреплённые темы, фоновый мониторинг, доставка, суммаризация, NER, семантическая дедупликация одного события.

## Эталонные запросы (для qual-теста)

1. «курс валют»
2. «ставка ЦБ»
3. «санкции против РФ»
4. «IT-импортозамещение»
5. «сделки M&A в финтехе»
6. «новости про автоваз» — узкая тема, проверка что не вернётся всё подряд
7. «дай мне всё что было за неделю про сделки M&A в финтехе с участием Сбера и ВТБ» — длинный сложный запрос

Для каждого: команда вручную просматривает топ-10 за 7 дней по источникам, фиксирует «ожидаемое» множество. После прогона сравниваем.
