# NewsCore AI — MVP brief

> Документ для согласования с командой. Версия: 2026-05-18.
> Основан на: `concept.md`, `research.md` + обсуждение в командном чате 18.05.

---

## TL;DR

Тыкабельный веб-MVP: пользователь вбивает интересующую тему обычным языком («дай мне новости про курс валют»), агент собирает свежие материалы из ограниченного списка источников и возвращает брифинг (заголовок + краткое резюме + ссылка на оригинал). Брифинг можно «закрепить» — он становится **темой**, которая обновляется по расписанию и сигналит, когда появилось что-то новое.

Цель — не продукт в продакшене, а **демо к защите**, которое реально работает локально и в которое заказчик может потыкаться.

---

## Цель MVP

- Показать на защите рабочий end-to-end сценарий: запрос → брифинг → закрепление → обновление.
- Снять основной риск гипотезы: **сможет ли агент дать достаточно релевантный брифинг, чтобы пользователь не возвращался к ручному чтению.**
- Получить тыкабельный артефакт, который можно открыть с ноутбука и не упасть.

**Что осознанно НЕ цель MVP:**
- Продакшен-нагрузка, регистрация пользователей, монетизация.
- Деплой в Yandex Cloud (запускаем локально, по консенсусу из чата).
- Покрытие всех 15+ источников из исходной концепции — берём 3–5.
- Точность ML-пайплайна уровня медиалогии.

---

## Пользовательский сценарий (демо-флоу)

1. Пользователь открывает веб-приложение (одна страница).
2. В поле ввода: «новости про курс валют за последнюю неделю».
3. Жмёт «Собрать брифинг» → видит индикатор работы.
4. Через ~5–20 секунд получает список из N (например, 5–10) карточек:
   - Заголовок
   - 2–4 предложения суммаризации
   - Ссылка на оригинал + название источника + дата
5. Жмёт «Закрепить как тему» → брифинг превращается в **закреплённую вкладку** в боковой панели.
6. Закреплённая вкладка автоматически обновляется (раз в день / раз в неделю — пусть выбирает при создании).
7. Когда в обновлении появились новые карточки, на вкладке загорается индикатор «новое».

Лимит закреплённых вкладок: **3–5** (под обсуждение).

## Что входит в MVP

### Frontend (веб)
- Одна страница: поле ввода + список карточек брифинга.
- Боковая панель с закреплёнными темами.
- Индикатор «новое» на вкладке.
- Кнопка «закрепить» / «открепить» тему.
- Никакого онбординга по роли, никаких тарифов, никакого профиля.

### Backend
- API: создать брифинг по запросу, закрепить тему, получить обновления.
- Парсер источников (см. ниже).
- ML-инференс: одна модель — суммаризация.
- Хранилище: SQLite или Postgres (под обсуждение, см. вопросы) — для тем и кэша новостей.
- Планировщик: раз в N часов прогоняет все закреплённые темы.

### ML — только суммаризация на старте
- Модель: `sberbank-ai/ruT5-base` (по согласованию из чата).
- Альтернатива на обсуждение: использовать LLM API на первом шаге для скорости, ruT5 подключить позже.
- Фильтрация по релевантности на старте — простой keyword/BM25 матч между запросом пользователя и заголовком/телом новости. Без NLI.

### Источники (на старте)
- 3–5 русскоязычных деловых RSS (РБК, Коммерсантъ, Forbes Russia, Ведомости — итог под утверждение).
- Полагаемся только на **открытые RSS-фиды**, чтобы не упереться в TOS/правовые вопросы для демо.

## Что НЕ входит в MVP (отложено)

| Фича | Почему отложено |
|---|---|
| NLI-проверка («предикат vs текст») | Усложняет пайплайн; начинаем без неё, добавим если в брифингах будет много нерелевантного |
| NER (`DeepPavlov/rubert-base-cased-ner`) | Нужно для importance scoring / фасетов; на MVP не критично |
| Классификация по категориям (`ruBERT`) | Категории не нужны, пока интерес задаёт сам пользователь текстом |
| YandexGPT | По обсуждению — не нужен; русскоязычная суммаризация делается ruT5 / open-source |
| Деплой в Yandex Cloud | Демо локально с ноутбука; деплой — отдельная задача |
| Telegram-бот / Mini App | Только веб |
| Email-рассылка дайджестов | Только веб |
| Регистрация / профили / роли (инвестор/МСБ/...) | Не нужно для демо |
| Тарифы (Free / Pro) | Не нужно для демо |
| 15+ источников | На демо хватит 3–5 |

## Технический стек (предложение, под утверждение)

| Слой | Предложение | Альтернативы |
|---|---|---|
| Frontend | React + Vite (или Next.js, если нужно SSR — для MVP скорее нет) | — |
| Backend | FastAPI (Python) | Node/Express, если в команде сильнее JS |
| ML-инференс | HuggingFace `transformers` локально, ruT5-base | LLM API (быстрее запустить) |
| Парсинг | `feedparser` для RSS + `trafilatura` для очистки HTML тела статьи | — |
| Хранилище | SQLite (для демо хватает) | Postgres, если ожидаем сразу нагружать |
| Планировщик | APScheduler или cron внутри backend | Celery beat (избыточно для MVP) |
| Запуск | `docker-compose up` или просто два процесса локально | — |

## ML-пайплайн (поэтапно)

```
RSS-фиды
  → парсинг + извлечение тела статьи
  → дедупликация по URL
  → фильтр по релевантности запросу (keyword/BM25)
  → суммаризация (ruT5-base)
  → карточка в UI
```

Что добавляется на следующих шагах (после MVP):

1. **NLI** — отсев нерелевантных карточек проверкой предиката пользователя против тела статьи (`xlm-roberta-large-xnli`).
2. **NER** — извлечение сущностей для importance scoring и фасетной навигации (`DeepPavlov/rubert-base-cased-ner`).
3. **Классификация** — категоризация по темам (`ruBERT`), если понадобится для UX.

Принцип: каждый слой добавляется отдельно, измеряется на простом качественном тесте, и оставляем только если реально улучшает брифинг.

## Открытые вопросы для команды

Прошу ответить да/нет/свой вариант, чтобы зафиксировать scope:

1. **Сроки.** К какой дате нужен тыкабельный демо? (Защита когда?)
2. **Команда и роли.** Кто пишет backend, кто frontend, кто отвечает за ML? Можно ли мне закрыть несколько ролей сразу?
3. **Источники.** Окей фиксировать 3–5 RSS на старте? Какие именно? (Предлагаю: РБК, Коммерсантъ, Forbes Russia, Ведомости, Интерфакс.)
4. **LLM-первый шаг.** Окей ли начать с LLM API для суммаризации (быстрее запустить), а ruT5 подключить вторым шагом? Или сразу строимся на ruT5-base локально?
5. **Лимит закреплённых тем.** 3 / 5 / больше? (Влияет на UX и нагрузку.)
6. **Период обновления.** Фиксируем «раз в день» по умолчанию или даём пользователю выбор (час / день / неделя)?
7. **Что входит в карточку брифинга.** Заголовок + summary + ссылка + источник + дата — хватит? Нужны ли теги/сущности?
8. **Хранилище.** SQLite окей для демо или сразу Postgres?
9. **Запуск демо.** На ноутбуке у кого-то из команды, или всё-таки минимальный публичный URL (Cloudflare tunnel / ngrok)? Дима предлагал не париться с деплоем — подтверждаем?
10. **Юридика.** Используем только RSS-фиды (там обычно по правилам можно резюмировать со ссылкой). Это для нас приемлемо или нужна доп. проверка?
11. **Регистрация.** Демо без авторизации (одна сессия в браузере = один пользователь)? Или нужен хотя бы вход по email/коду для разделения тем?
12. **Метрика успеха демо.** Что должно произойти на защите, чтобы мы посчитали MVP удачным? («Заказчик потыкал и сказал X»? Конкретный сценарий?)
